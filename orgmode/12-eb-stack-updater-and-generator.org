#+begin_objectives
1. Given a conda-forge recipe or a Spack =package.py=, name the command
 that writes the =.eb=, and say what still has to be built.
2. Read a bump: name every pin that moved with the toolchain, and the
 lines that did not.
3. Tell a port of software EasyBuild does not have from an annual
 retarget of software it does.
#+end_objectives
eb-stack performs two tasks.
One task is a *port* that takes input from conda-forge or Spack and produces an EasyBuild recipe.
The other task is a *bump* that rewrites an easyconfig written for one toolchain generation for the next.
Neither task invokes =eb=.
Both generate files that a human then builds.
[[https://eb-stack.rgoswami.me][eb-stack]] is the tool.
A planned CycloneDX SBOM is one of the files it writes.
The next figure is that SBOM for a GROMACS bump, drawn by =eb-stack stack graph= (and by =scripts/sbom_to_dot.py=).

* A port starts as someone else's recipe
The conda-forge feedstock for eOn 2.16.0 is frozen in eb-stack's fixtures.
It includes name, version, sources, host dependencies, and tests.
It is not an easyconfig.

The command =package plan= converts the file to an easyconfig.
=--format conda-forge= selects the parser.
=--stack-policy= is required.
#+begin_example
eb-stack package plan \
 --source fixtures/foreign_ingest/conda_eon/recipe.yaml \
 --format conda-forge \
 --toolchain-name foss \
 --toolchain-version 2024a \
 --package-config examples/packages/common.toml \
 --package-config examples/packages/eon.toml \
 --easyconfigs /path/to/easybuild-easyconfigs \
 --stack-policy site/foss-2024a.toml \
 --out-dir /tmp/eon-from-conda
#+end_example
What comes out is a tree, not a speech:
#+begin_example
package.plan.json
package.sbom.cdx.json
locks/default.lock.json
easyconfigs/e/eOn/eOn-2.16.0-foss-2024a.eb
#+end_example
The =.eb= is an emitted recipe, not an artifact EasyBuild compiled.
Lock denotes solver assignment.
Plan includes parsed foreign recipe and residuals; parser‑invented items appear as typed leftovers, not guessed dependencies.
[[file:33-inspect-residuals-and-the-plan.org][Inspect writes a work queue, not a recipe]].
The feedstock and the Spack recipe sit next to each other.
Name and version remain retained.
=eon= transformed into =eOn=.
=eigen >=3.4,<3.5= converted into pin for this generation.
=libtorch= renamed to =PyTorch=.
Meson flags originally set by feedstock's =build.sh= now represented as =configopts=.

Three sources are used.
The =target_directory: subprojects/rgpot= entry became a staged extract in the full file; the widget above keeps the names.
In the full recipe, =sanity_check_commands= runs =eonclient --version= and =python -c "import eon"=; this mirrors the feedstock's =tests:= block.
A Spack =package.py= file is the other input.
The paper [[cite:gamblinSpackPackageManager2015][Gamblin et al. 2015]] describes that format.
A spec is a DAG of constraints (name, versions, variants, compiler, arch, deps). A concretiser selects one graph.
The same software is parsed differently.
=--format spack= specifies the parser.
The file is Python and is *not* executed; literal =depends_on= and =version= calls are interpreted as syntax.

~depends_on("eigen@3.4:")~ (eigen 3.4 or newer) defines a range.
EasyBuild does not support ranges ([[file:03-a-pin-is-for-one-generation.org][A pin is for one generation]]).
The solver selects =Eigen-3.4.0= from the robot tree for that generation.
A =def patch(self):= that executes sed is not a file.
It becomes a =judgment= residual.
The emitted =.eb= does not claim that the sed occurred.
Inspect writes the work queue. The campaign then runs it.
The queue is visible first.
Plan then consumes the robot tree only for items already decided.
=package inspect= uses the same parsers without performing the solve.
It writes =package.plan.json=.
It writes a planned SBOM.
It produces no =.eb=.
Use it to read residuals.
Use =package plan= to select non‑blocking items.
Use =package plan= to emit the file.
* A bump starts as an easyconfig that already works
GROMACS 2024.4 builds with =foss/2023b=.
The file exists.
The yearly job uses the same software on =foss/2024a=.
Manual copying of the file and alteration of four version strings creates pins that become undocumented floors.

Use the same command with =--version= and =--source-checksum= to increase the *application* version.
If the checksum is omitted, the tarball name changes.
The hash becomes stale.
That missing hash is a blocking residual, not a guessed checksum.
* Two commands, then =eb=
| Job | Command | Input | Output |
|---+---|---|---|
| read a foreign recipe | =package inspect= | =recipe.yaml= / =package.py= | plan + SBOM, no =.eb= |
| port it | =package plan= | the same, plus a robot tree and a stack policy | plan, lock, =.eb= |
| retarget a generation | =package bump= | an existing =.eb= plus a robot tree | plan, lock, new =.eb= |
| build what was written | =campaign run= | the bundle | =eb=, on a named target |

=recipe lint= examines the file.
=recipe check= examines the file.
See [[file:34-recipe-format-lint-check.org][Format, lint and check are three different questions]].
=campaign run= is the initial command that performs compilation.
See [[file:36-campaign-findings.org][A campaign finding is a typed failure, not a log]].
A green plan represents the claim =resolves=.
It does not represent the claim =builds=.
#+ATTR_EB: :id EB-Port-1 :title Port, bump, or neither
#+begin_exercise
Four starting points. For each, name the eb-stack command, or
say the work is not eb-stack's.

1. [[https://github.com/HaoZeke/eb-stack/blob/main/fixtures/foreign_ingest/spack_qmcpack/package.py][fixtures/foreign_ingest/spack_qmcpack/package.py]], no
 QMCPACK easyconfig in the robot.
2. [[https://github.com/easybuilders/easybuild-easyconfigs/blob/develop/easybuild/easyconfigs/g/GROMACS/GROMACS-2024.4-foss-2023b.eb][GROMACS-2024.4-foss-2023b.eb]], site moving to =foss/2024a=.
3. The =.eb= from (1), in a bundle, nobody has run =eb=
 yet.
4. A tarball and a README, no conda-forge recipe, no Spack
 package, no easyconfig.

#+begin_solution
1. =package plan --format spack=. Inspect first if the residuals
 are unknown. The output is an easyconfig plus a lock.

2. =package bump=. The source is already an easyconfig. The
 robot tree for 2024a is the candidate set.

3. =campaign run=, or =eb= on that file. eb-stack has finished
 the generator's job.

4. [[file:21-writing-one-from-nothing.org][Writing one from nothing]]. There
 is nothing to parse. The five mandatory parameters are
 written by hand.
#+end_solution
#+end_exercise

#+begin_keypoints
- A port reads conda-forge or Spack and writes an easyconfig.
 =package plan --format conda-forge= or =--format spack=.
- A bump reads an easyconfig and writes the same software on a
 new toolchain generation. Application version, sources and
 patches stay; every pin that lives on the toolchain moves.
- A Spack =eigen@3.4:= is a lower bound. The robot either finds a
 pin this generation ships or the range stays a residual.
- Nothing in inspect, plan or bump compiles the package.
 =campaign run= calls =eb=.
#+end_keypoints
