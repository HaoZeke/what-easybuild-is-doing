#+TITLE: What EasyBuild Is Doing
#+AUTHOR: Rohit Goswami
#+OPTIONS: toc:nil num:nil

This book is about what EasyBuild is doing. EasyBuild's own
documentation tells you what to type and stays almost silent on what
happens when you do.

That silence is expensive. EasyBuild has reference documentation for
every parameter, and a workshop series with hands-on exercises. Between
them they will get you to a working install. Neither explains why an
easyconfig is a Python file, or why a toolchain is a hierarchy rather
than a name. Neither explains why the version number next to a
dependency is not a minimum. People learn those three things by
breaking a production software stack, which is a slow and public way to learn
them.

So this is the other book. You need to be able to read code. You do not
need EasyBuild installed, and you do not need a cluster. The samples in
it run in your browser.

* What you need

Nothing. That is the point.

EasyBuild's own tutorial opens by asking for Linux, Python, an
environment modules tool and a working EasyBuild install. That is a
reasonable ask of someone who has already decided to use EasyBuild. It
is an unreasonable one of someone still deciding whether to. What runs
here runs on your machine, in the page.

Three of the four sample kinds run: template resolution, the easyblock
name, and the toolchain hierarchy. Each works off a table exported from
eb-stack at build time rather than retyped. So a page cannot drift from
the framework's own data, and a cross-check compares the browser's
answers against the binary's on every build.

The fourth needs a Python parser, which is the one thing here no table
replaces. That sample shows the exact input it will take and says it is
read-only. The answer sits in the prose beside it until the engine
compiles to WebAssembly.

That gets you a lot, and not everything. Nothing in a browser can
configure, compile or link, and nothing here pretends to. Where a step
needs a real toolchain you get a recording of a real run instead. That
turns out to be the right way to teach it: the operational skill is
reading the log, not watching the progress bar.

Chapters are published as they are written, and each one reads on its
own. If you read exactly one, read the first. If you read two, read the
third as well. The version number beside a dependency is the single
most expensive misreading in EasyBuild, and it is four lines long.

Chapters 1 to 4 are the mechanisms everything else rests on. Chapters
5 to 9 are the parameters that cost real time when misread, each built
around a failure that actually happened. Chapter 10 argues for the
other tools.
