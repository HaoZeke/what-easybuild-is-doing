#+TITLE: What EasyBuild Is Doing
#+AUTHOR: Rohit Goswami
#+OPTIONS: toc:nil num:nil

I want to tell you what EasyBuild is doing, because EasyBuild's
documentation is very good at telling you what to type and almost
silent on what happens when you do.

That silence is expensive. EasyBuild has reference documentation for
every parameter and a workshop series with hands-on exercises, and
between them they will get you to a working install. Neither explains
why an easyconfig is a Python file, why a toolchain is a hierarchy
rather than a name, or why the version number next to a dependency is
not a minimum. People learn those three things by breaking a
production software stack, which is a slow and public way to learn
them.

So this is the other book. It assumes you can read code, it does not
assume you have EasyBuild installed, and it does not assume you have a
cluster. The samples in it run in your browser.

* What you need

Nothing. That is the point.

EasyBuild's own tutorial opens by asking for GNU/Linux, Python, an
environment modules tool and a working EasyBuild install, which is a
reasonable ask of someone who has already decided to use EasyBuild and
an unreasonable one of someone deciding whether to. Everything
interactive here is a parser and a dependency solver compiled to
WebAssembly, running on your machine, in the page.

That buys a lot and it does not buy everything. Nothing in a browser
can configure, compile or link, and nothing here pretends to. Where a
step needs a real toolchain you get a recording of a real run instead,
which turns out to be the right way to teach it: the operational skill
is reading the log, not watching the progress bar.
