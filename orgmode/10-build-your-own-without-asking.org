#+TITLE: Chapter 10. Build your own, without asking anyone
#+OPTIONS: toc:nil num:nil

#+begin_objectives
1. Install software into a directory the operator owns, on a machine where that operator is
   not an administrator.
2. Read =--show-config= and say where each value came from.
3. Name the three lists involved, and say which one your prefix does not
   touch.
#+end_objectives

EasyBuild does not need administrator rights. Point it at a directory
the current user owns:

#+begin_src ebtranscript :source "SURF Snellius, int4 interactive node, 2026-09-09, EasyBuild 5.3.1" :caption "One environment variable, eight paths"
$ export EASYBUILD_PREFIX=$HOME/eb-demo
$ eb --show-config
#
# Current EasyBuild configuration
# (C: command line argument, D: default value, E: environment variable,
 F: configuration file)
#
buildpath         (E) = /home/rohitg/eb-demo/build
bwrap-installpath (E) = /home/rohitg/eb-demo/bwrap
containerpath     (E) = /home/rohitg/eb-demo/containers
installpath       (E) = /home/rohitg/eb-demo
packagepath       (E) = /home/rohitg/eb-demo/packages
prefix            (E) = /home/rohitg/eb-demo
repositorypath    (E) = /home/rohitg/eb-demo/ebfiles_repo
robot-paths       (D) = /sw/noarch/RHEL9/2025/software/EasyBuild/5.3.1/easybuild/easyconfigs
rpath             (D) = True
sourcepath        (E) = /home/rohitg/eb-demo/sources
sourcepath-data   (E) = /home/rohitg/eb-demo/sources
#+end_src

Read the letters in brackets before anything else. That legend is the
configuration model, printed. A value came from the command line, a
configuration file, the environment, or a default, and =--show-config=
says which, for every setting. Precedence runs in that order: a flag
beats a variable, and a variable beats a file.

Eight settings say =(E)= from one variable.

* And one that did not move

=robot-paths= says =(D)=. Still the default, still pointing at the
easyconfigs that came with the site's EasyBuild.

Your prefix decided where output goes. It did not touch where EasyBuild
*looks*, and [[file:04-the-robot.org][chapter 4]] is why: those are two
different lists.

The site's easyconfigs stay available. Any of the thousands they
cover can be built without copying them. A local directory goes in
front when a site recipe is not enough:

#+begin_example
export EASYBUILD_ROBOT_PATHS=$HOME/my-easyconfigs:
#+end_example

The trailing colon is chapter 4's empty element, and here it earns its
keep: your directory first, the site's defaults still behind it. Leave
the colon off and the defaults are gone.

* The third list, which is the one people forget

There is a list your prefix did not touch and =--show-config= does not
print, because it does not belong to EasyBuild: =MODULEPATH=.

Chapter 4 showed the robot asking the module system what is installed,
through =modtool.available()=. So =MODULEPATH= decides what counts as
already built. Keep the site's modules on it, or drop them, and the
build goes two different ways.

Keep the site's modules on =MODULEPATH=, which they are by default, and
every dependency the site already installed is satisfied. The remaining
one package and nothing else. Twenty minutes, not two days.

Your own modules, though, are not on it. They are in your prefix, and
nothing put them there. So after the build:

#+begin_example
module use $EASYBUILD_PREFIX/modules/all
#+end_example

Miss that and the symptom is confusing out of proportion to its cause.
The build succeeded, the tree is on disk, and =module avail= does not
list it. The module system has not been told to look.

=modules= is the default =subdir-modules=, and =all= is where the
default naming scheme files them. Confirm it: build one
thing and read the path EasyBuild prints, or check =--show-config=.

* The whole path, once

Putting it together, on a cluster whose EasyBuild is loaded as a module:

#+begin_example
module load EasyBuild

export EASYBUILD_PREFIX=$HOME/eb
export EASYBUILD_ROBOT_PATHS=$HOME/my-easyconfigs:

eb --show-config                        # confirm the four lines above
eb GROMACS-2025.2-foss-2025a.eb -r -D   # read the plan first
eb GROMACS-2025.2-foss-2025a.eb -r      # then build it

module use $EASYBUILD_PREFIX/modules/all
module avail GROMACS
#+end_example

The =-D= line is not optional politeness. Chapter 4's plan is a
function of what is installed on *this* machine. So it is the only
thing that reports whether the plan is one build or ninety. Read
it, then decide.

If the site has no EasyBuild module, install one into a virtual
environment and use that instead. It is a Python package, and the
prefix and robot path work the same way afterwards.

#+ATTR_EB: :id EB-Own-1 :title It built, and it will not load
#+begin_exercise
You set =EASYBUILD_PREFIX=$HOME/eb=, ran a build, and it finished. The
tree is on disk under =$HOME/eb/software=. =module avail= does not list
it.

1. Which of the three lists is wrong, and why is it not either of the
   other two?
2. What is the one command that fixes it?
3. A colleague hits the opposite problem: their build takes all night and
   rebuilds forty things the site already has. Which list is wrong for
   them?

#+begin_solution
=MODULEPATH=. The robot path was fine, because the build found every
easyconfig it needed. The prefix was fine, because the software is on
disk where you asked for it. Nothing is broken. You have not told the
module system to look in your prefix.

=module use $EASYBUILD_PREFIX/modules/all=.

Your colleague has the same list wrong in the other direction. Something
has dropped the site's module tree from =MODULEPATH=, so nothing counts
as already built and the whole closure becomes theirs to compile.
Chapter 4 restated: the robot path decides what can be found, and
=MODULEPATH= decides what counts as already there. This is the one
EasyBuild does not set for you.
#+end_solution
#+end_exercise

* What this costs

Disk. Software plus sources plus build directories under one prefix, in
a home directory with a quota. Point =sourcepath= at a shared download
cache if the site has one, and clean the build directory.

Time. From-source is [[file:afterword-when-easybuild-is-the-wrong-tool.org][the afterword]]'s trade, and it does not get cheaper
because the operator is the one waiting.

Duplication, if =MODULEPATH= is wrong. Drop the site's modules and
every dependency becomes yours to build, which is how a twenty-minute
job becomes an overnight one.

And support. A module in your prefix is yours. When it breaks after a
system change, nobody else is going to notice.

The same prefix works against the site's EasyBuild and, once it is
mounted, against EESSI. When the robot has no recipe, generate or
bump a =.eb= and still run =eb=.
