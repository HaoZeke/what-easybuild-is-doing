import reframe as rfm
import reframe.utility.sanity as sn
from reframe.core.builtins import sanity_function, performance_function

@rfm.simple_test
class stream_test(rfm.RunOnlyRegressionTest):
 valid_systems = ['*']
 valid_prog_environs = ['*']
 executable = 'stream.x'

 @sanity_function
 def validate(self):
 return sn.assert_found(r'Solution Validates', self.stdout)

 @performance_function('MB/s')
 def copy_bw(self):
 return sn.extractsingle(r'Copy:\s+(\S+)', self.stdout, 1, float)

 @performance_function('MB/s')
 def triad_bw(self):
 return sn.extractsingle(r'Triad:\s+(\S+)', self.stdout, 1, float)

=@rfm.simple_test= is a decorator.
The class registers with the framework when the file is imported.
That registration appears in the output of =reframe -c stream.py -l=.
Without the decorator the class remains ordinary Python.
ReFrame does not see the class.
=RunOnlyRegressionTest= is the other claim on that line.

* Two constraints, then a verdict
Each test must define =valid_systems= and =valid_prog_environs=.
These entries are not documentation.
The framework filters tests using the current system and the current programming environment.
A test that matches neither is not scheduled.
=['*']= denotes any system and any environment.
The tutorial's starting point is =['*']=.
A claim using this placeholder must be narrowed when the test leaves a laptop.
Each test must also define a validation function decorated =@sanity_function=.
ReFrame makes no default assumption about test success.
The exit code is not examined.
[[cite:karakasisEnablingContinuousTesting2020][Karakasis et al. 2020]] state the design goal as productivity.
The test writer focuses on logical requirements.
The framework handles the job script, the scheduler, and the output files.
The corollary surprises users of =make test=.
*a process that exits zero and prints nothing has failed*.
=sn.assert_found= looks in =self.stdout=.
=self.stdout= is the file containing the job's standard output.
It is not a live stream.
The pattern is a regular expression.
The STREAM binary prints =Solution Validates= when the array checksum matches.
That string is the entire correctness claim of this test.
The two =@performance_function= methods are optional.
They extract figures of merit and give them a unit.
A performance function is a numeric value with a unit.
They do not determine test *passed* status.

#+ATTR_EB: :id EB-ReFrame-39-1 :title What decides a pass
#+begin_exercise
The STREAM binary is replaced by one that exits 0 and prints only
=Copy: 19000.0=. The sanity function is unchanged. Does the test
pass? Which phase fails, and why is the exit code not the answer?
#+begin_solution
It fails in the sanity phase. =assert_found= looks for
=Solution Validates= in =stdout= and does not find it. The exit code
is 0 and is never consulted. ReFrame's default is that a test is
unsuccessful until a sanity function says otherwise; an empty or
partial log is a failed test, not a quiet success.
#+end_solution
#+end_exercise

#+begin_keypoints
- A ReFrame test is a decorated Python class. Without =@rfm.simple_test=
 the class is never registered.
- =RunOnlyRegressionTest= skips compile. The executable is assumed to
 exist.
- =valid_systems= and =valid_prog_environs= are filters, not comments.
 =['*']= means any.
- ReFrame does not look at the exit code. A sanity function is the
 verdict, and a missing pattern is a failure.
#+end_keypoints
