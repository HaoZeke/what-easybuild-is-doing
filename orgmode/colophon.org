* Where this runs
EasyBuild is a Python package.
It installs with =pip= into a virtual environment, needs a modules tool and a compiler, and builds software on a laptop exactly as it does on a compute node.
The failing build in [[file:20-reading-a-failed-build.org][Reading a failed build]] and the checks in [[file:21-writing-one-from-nothing.org][Writing one from nothing]] ran on a workstation.
EESSI's installation instructions cover a laptop.
CernVM-FS ships a client profile for that case.
[[file:26-the-same-stack-somewhere-else.org][The same stack somewhere else]] does it on four kinds of machine.
On a large shared machine the *consequences* change, not the mechanism: more users than maintainers, one tree, a scheduler, several microarchitectures, and a rebuild that costs somebody a night.
* What the samples are
A browser is provided.
Every sample runs in the page.
Editing a sample changes the answer while typing.
Pressing Escape opens a playground.
Three of the four kinds operate on tables exported from eb-stack at build time.
A cross-check compares the browser answers against the binary on each build.
The fourth reads an easyconfig into its evaluated model.
It is a reduced reader rather than the real parser.
It follows single-line assignments and *names what it skipped*.
No browser functionality can configure, compile, or link.
When a step requires a real toolchain the page displays a recording of a real run, with where and when printed beside it.
* Who wrote this
Rohit Goswami maintains software stacks on a national machine.
Rohit Goswami runs the same tools on a laptop.
Rohit Goswami wrote [[https://eb-stack.rgoswami.me][eb-stack]]. eb-stack is the updater and generator that emits the =.eb= files EasyBuild then builds.
The samples on these pages borrow tables from that generator.
The samples are not the generator.
The samples are not EasyBuild.
