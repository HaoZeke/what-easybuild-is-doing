* Step 1: what the file says, and what it means
A real easyconfig is provided. 
It installs a browser‑based VS Code on a supercomputer. 
Read the easyconfig first. 
Read the answer underneath it next.
#+begin_src easyconfig :widget parse :hydrate load
name = 'code-server'
version = '4.130.0'

homepage = 'https://github.com/coder/code-server'
description = """Run VS Code on any machine anywhere and access it in the browser."""

toolchain = SYSTEM

source_urls = ['https://github.com/coder/code-server/releases/download/v%(version)s/']
sources = ['code-server-%(version)s-linux-%(mapped_arch)s.tar.gz']

moduleclass = 'tools'
#+end_src
The evaluated model includes three items missing from the file above. 
=toolchain= reads =({name: system, version: system})= rather than the word =SYSTEM=. 
EasyBuild places that name in scope before evaluating the file, using the constant ={'name': 'system', 'version': 'system'}=. 
It is a variable and =moduleclass= adjacent to it is a string. 
=source_urls= returns =4.130.0=. 
After the file runs, EasyBuild performs a second pass that formats the =%(version)s= strings. 
The file itself stored the literal value. 
File order is irrelevant; =sources= may appear before =version=. 
The final line reports an easyblock that the file never mentions.

* Step 4: which easyblock will EasyBuild look for
An easyconfig lacking an =easyblock= assumes a software-specific one exists. 
EasyBuild derives the name by converting the software's name one character at a time. 
Provide multiple names in this field. 
Add your own software when it is available.
#+begin_src easyconfig :widget easyblock :hydrate load
code-server
c++
Xerces-C++
Python-bundle-PyPI
GROMACS
#+end_src
Rewrite this org-mode prose. 
Keep org markup such as =foo= and [[links]]. 
*Expected output.* 
punctuation spelled out as words: the hyphen in =code-server= becomes =minus=, and =c++= becomes =EB_c_plus__plus_=. 
Look at the doubled separator in the middle. 
The substitution runs per character and collapses nothing, and that is what keeps it reversible. 
Now type a name with an underscore in it, say =my_tool=. 
*Expected output.* 
=_underscore_= . 
That character is encoded too, and it has to be. 
Left alone, =_minus_= could mean either an encoded hyphen or a name that really contained the letters =minus=. 
Two things follow. 
Given a name, you know which file EasyBuild will try to import. 
And given a class name in a traceback, you can read it backwards to the software.
* Step 5: what a toolchain lets you see
A dependency is a candidate only if built with a toolchain that exists in the package's hierarchy. 
Identify the contents of a hierarchy.
#+begin_src easyconfig :widget hierarchy :hydrate load
toolchain = {'name': 'foss', 'version': '2025a'}
#+end_src
Provide a chain from =system= up to =foss-2025a=, with the most minimal first, and include a note about two of the members. 
A package on =foss-2025a= may depend on any component built with any member of that list. 
A package on =GCCcore= cannot depend on a =foss= build. 
The rule is not a matter of politeness; the dependency is not a candidate, causing the robot to report that it cannot locate something visible on disk. 
Change =2025a= to =2024a=, then to =1999z=. 
Provide a different chain, followed by a refusal indicating which generations the page knows. 
A hierarchy reflects what is installed rather than the string.

* What you now know
Five items are described; the first four correspond to previous actions. 
An easyconfig is Python code evaluated in a prepared namespace. 
Unquoted names represent variables supplied by EasyBuild. 
=%(...)s= is Python's own formatting applied to a dictionary assembled by EasyBuild. 
A value resolves to content not explicitly stated in the file. 
The easyblock is derived by transforming the name. 
A file lacking an easyblock line implicitly refers to an existing easyblock. 
A toolchain defines the top of a hierarchy; the hierarchy determines permissible dependencies. 
The fifth point, observed twice, states that when resolution fails, the tool reports the failure instead of guessing. 
A blank =version=, an unknown generation, or a structure the reader cannot follow each is an unresolved case. 
Each case is reported. 
Many costly errors arise from providing guesses that the tool declined to make.
